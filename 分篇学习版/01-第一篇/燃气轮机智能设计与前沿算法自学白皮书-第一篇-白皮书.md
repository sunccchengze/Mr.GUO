### 【第01讲】CR-EI：贝叶斯优化为什么会"瞎逛"——过度探索的发现与校准（**论文 01**）

#### 本讲开场 90 秒

**上讲闪回（第零章）：** 叶片设计是 HEB 问题——维数高、每次 CFD 贵、没有导数。全书都在问：下一笔预算该砸哪？

**本讲反派：** 「瞎逛」——采样次数已经很多，算法却在明显很差的空白区打转，出不来。

**只要带走 3 句口诀：**

1. **病根是 z ≤ 0**：不确定度 σ 大的地方，未必是好地方。  
2. **治则是改 ξ，不是改 σ**：前人爱调探索权重；本文抬高"当前最优"这根尺子。  
3. **近处 CEI、远处 REI，EI 瞎了再换班**：值班经理三规则。

![第01讲心智图：z、瞎逛与 CR-EI 调度（手绘笔记版）（mindmap）](../../images/L01_h_mindmap_zh.png)

> **看图三秒：** 中间是参数 z；左边 z>0 是"有希望的街区"；右边 z≤0 是工业区瞎逛；底部三条口诀请先刻住，后面只是在证明它们。

**本讲赌注：** 若放任 z≤0 的瞎逛，有限 CFD 预算会永久巡逻工业区。

#### 1. 生活与物理直觉引子：三种"找最佳餐厅"的策略

![restaurant map 口味地图：z>0 好街区 vs z≤0 工业区瞎逛](../../images/L01_d_restaurant_map_zh.png)

> **指读：** 左有希望区、右工业区巡逻；CR-EI 改的是尺子 ξ 与近远分工。

假设你搬到一座新城市，给自己定了死规矩：**30 天内，找到全城最好吃的那家面馆。**

每一顿饭都要花钱、花时间——这顿饭就是一次**昂贵实验**。放到叶片设计里，它对应动辄几小时的一次 CFD。

你口袋里的钱，只够吃大约几十顿。于是策略选择，比"爱吃辣还是爱清汤"更要命。

![找面馆三策略漫画（restaurant comic，教学比喻）](../../images/L01_m_restaurant_zh.png)

> **指读：** 左格人死守小巷（河对岸的神店永远没机会）；中格人专钻空白工业区（反复确认"这儿难吃"）；右格人手里有一张口味地图——颜色深的是已知好吃，问号是不确定。

**策略 A · 纯开发（exploitation）**  
找到一家还不错的，就天天去，只在附近小巷换着吃。  
风险：全市第一在河对岸，你这辈子不会知道。

**策略 B · 纯探索（exploration）**  
专挑地图上空白的地方。  
风险：空白区常常是没人去的工业区，你只是在验证"确实难吃"。

**策略 C · 聪明折中**  
维护一张"口味地图"：  
- 已知好吃的街区 → 猜附近也可能好吃；  
- 空白处 → 标成"不确定"，不确定越大，越值得去试试。

贝叶斯优化里的**期望改善（Expected Improvement, EI）**，就是策略 C 的数学版。

本讲要讲的，是策略 C 里一个**藏了二十年**的陷阱：地图用着用着，会把你系统性、持续地推进工业区——而且还可能**永远出不来**。我们给它起个绰号：**瞎逛**。

| 生活元素 | 工程元素 | 本讲符号（先混个眼熟） |
| :--- | :--- | :--- |
| 面馆坐标 | 设计变量 | x |
| 口味得分 | 性能（如 −L/D、损失） | y |
| 口味地图的"估计均分" | 代理模型预测均值 | ŷ(x) |
| 地图上的"不确定带宽" | 预测标准差 | σ(x) |
| 目前吃过的最高分 | 当前最优（incumbent） | ξ |
| 要不要再去这家的冲动 | 期望改善 | EI(x) |

> **先猜后揭：** 若算法开始专挑"地图上最空白、但也最可能难吃"的点，病在地图（σ）还是在尺子（ξ）？  
> 揭晓在 §3：主流改 σ，本文改 ξ。

**策略 C 的藏二十年陷阱（加长）：**  
口味地图用着用着，会系统性把你推进工业区：好区被采密后 σ 变小，差区反而更空、σ 更大，EI 听空白的话。  
这不像偷懒，像勤奋——所以叫**瞎逛**更阴。郭振东等指出过度探索与过度开发是一对病，只治贪不够。

#### 2. 叶轮机械中的真实工程死穴：算不起，但停不下

把面馆换成叶片。现场是这样的：

周五下班前，组长丢来一句话——「下个型号的叶型，预算只够再跑几百次 CFD，给我一个比现在更好的外形。」

你面对的不是一道可以慢慢推的数学题，而是一个**昂贵黑箱**：

![昂贵黑箱：设计参数、CFD 求解器与预算三者的关系（手绘笔记版）](../../images/L01_s2_expensive_blackbox_zh.png)

> **指读：** 左边塞进几何参数 x，中间黑箱是 CFD，右边吐出一个数 y。箭头上写着时间与金钱。

- 给一组几何参数 x（厚度分布、安装角、端壁型线……），求解器吐回性能 y；  
- 一次高保真 CFD 可能要**几小时到几十小时**；  
- 一个设计周期能负担的次数往往只有**几百到几千次**［原文 P07 §1］；  
- 设计变量轻易超过 **100 维**［原文 P07 摘要］。

![预算沙漏 hourglass：每一次采样都必须值回票价](../../images/L01_f_budget_hourglass_zh.png)

> **指读：** 上半斗是有限次数，每粒沙标着"1 小时"；下半斗是高维空间里稀疏的点。红章的意思只有一个——**点错一次，就烧一笔不可回收的预算。**

在这种现场，EI 成为贝叶斯优化的默认配置，是因为它直接回答：

> 「这个点，值得再花一次 CFD 吗？」

可 EI 有个久治不愈的毛病：**次数已经很多了，结果却卡在次优解上。**

此前学界常说：那是**过度开发**——算法太贪，只在当前最优点附近打转。

郭振东等指出：**这个解释只对了一半。** 还有一半叫**过度探索**，而且更阴险——它长得像"勤奋地探索"，其实是在工业区永久巡逻。这就是本讲反派 **瞎逛**。

**预算沙漏的第二读法：**  
上半斗是次数，下半斗是维数稀疏。  
EI 默认很香，是因为它直接回答「值不值得再花一次」；  
但当 z 掉到明显负值，它回答的其实是「空白大不大」，不是「空白处好不好」。  
CR-EI 的贡献，是把值班经理请回来：瞎了换班，而不是继续勤奋地错。

#### 3. 数学公式从 0 到 1 推导：一个参数 z，两种病

![z pocket card 速记：z 正负与瞎逛换班](../../images/L01_d_z_pocket_card_zh.png)

> **指读：** z≫0 过度开发；z≪0 瞎逛；治则抬 ξ、近 CEI 远 REI。

先把公式关掉。只用餐厅语言说一遍：

> 你的口味地图在每个位置给出两个量：  
> **估计均分** ŷ，和 **不确定带宽** σ。  
> 你还记得目前吃过的最高分 ξ。  
> 定义一个无量纲分数 z，衡量"最高分比估计均分高多少个不确定带宽"。  
> **z 很大** → 地图很有把握地说"这儿不如已经最好的那家"→ 你只会在已知好区精耕（贪）。  
> **z 很小（很负）** → 你几乎只听带宽 σ 的话 → 专往空白处钻；而空白处常常是差区 → **瞎逛**。

下面用符号把这话说死。本讲主文只留 **3 条核心式**；偏导与积分细节在深潜框，不挡路。

![一个参数 z、两种病：z<−3 过度探索与 z>3 过度开发（手绘手账版）](../../images/L01_s3_z_two_diseases_zh.png)

![高斯过程后验与期望改善采集函数（中文标注版）](../../images/gaussian_process_and_acquisition_zh.png)

> **指读 GP 图：** 上半幅是后验均值与置信带——样本越密，带子越瘦；下半幅是 EI 曲线，它在"预测更好"与"更不确定"之间拉扯。后面 CEI/REI/GEI 改的都是这张图上的东西。

##### 3C. 主路径只要三条式

**核心式 ① — z 的定义**

**〔式〕** z = (ξ − ŷ(x)) / (σ(x))

**回译：** z 是"比当前最优好（或差）多少个不确定带宽"。  
**停顿：** 若 σ 很大，分母大，z 的绝对值容易变小——地图会更听"空白"的话。

**核心式 ② — EI 的人话版（结构）**

EI 可以写成（原文式 5、式 11）：

**〔式〕** EI(x) = σ(x) · (z Φ(z) + φ(z)) = σ(x) · EI*(z)

**回译：**  
- 前面的 σ(x) 像"冲动的音量"；  
- 括号里的 EI*(z) 像"这首歌好不好听"。  
z 决定你唱的是开发调还是探索调。

**核心式 ③ — 符号约束（为什么瞎逛出不来）**

**〔式〕** z > 0 ⇒ ŷ(x*_EI) < ξ（被关在有希望区）；z ≤ 0 ⇒ 对 ŷ 无任何约束

**回译：**  
z>0 时，EI 选出的点，预测值必须优于当前最优——像只在"可能超越冠军"的街区转。  
z≤0 时，这道门消失。再叠加"σ 大的地方往往是早期没人去的差区"，算法就会**系统性地、持续地**冲进工业区。

**两种病（看图 L01_s3，不必先啃偏导）：**

| 病名 | z 的极端 | 行为 | 餐厅版 |
| :--- | :--- | :--- | :--- |
| 过度开发 | z > 3 | 几乎只跟 ŷ 走 | 死守已经好吃的小巷 |
| 过度探索（瞎逛） | z < −3 | 几乎只跟 σ 走 | 永久巡逻工业区 |

**论文里的触目惊心例子**［原文 P01 §3.1］：  
6 维 Hartman6 上，EI 用 LHS 撒 36 个初始点后很快陷入过度探索（z 在 −5 附近抖，σ²/σ²_max≈1，maxEI 从 10⁻⁵ 掉到 10⁻²⁰）。若按"maxEI 小于阈值就停"，得到 **−2.7890**，而真全局最优是 **−3.0424**。

**附带结论（仍属主路径）：** EI*(z) 在 z>0 近似线性好优化，在 z≤0 指数衰减、极难优化。所以**保持 z>0 是明智的**；但简单加阈值停机又会早熟。这就是 CR-EI 要解的死结。

> 【深潜｜可跳过】完整解析式、偏导与梯度权重
>
> 完整写法（原文式 5）：  
> **〔式〕** EI(x) = ∫_{−∞}^{ξ} (ξ − Y) dF_Y = (ξ − ŷ) Φ(z) + σ φ(z)
>
> 偏导（用于理解权重，不必会推）：  
> **〔式〕** ∂EI/∂ŷ = −Φ(z)， ∂EI/∂σ = φ(z)
>
> 负梯度：  
> **〔式〕** −∇EI(x) = Φ(z) (∂ŷ/∂x) − φ(z) (∂σ/∂x)
>
> - 第一项开发、第二项探索；权重分别是 Φ(z)、φ(z)。  
> - z>3 时 Φ≫φ → **〔式〕** −∇EI|_{z>3} ≈ Φ(z) (∂ŷ/∂x) → 过度开发  
> - z<−3 时 φ≫Φ → **〔式〕** −∇EI|_{z<−3} ≈ −φ(z) (∂σ/∂x) → 过度探索  
>
> 读完可以回到主文 §4，不影响值班手册。

#### 4. 算法控制流：EI / CEI / REI 三兄弟如何轮班

核心思想，一句就够：

> **别再拧 σ 那个旋钮了（前人都拧过）。改 incumbent 这根尺子 ξ。**

![EI / CEI / REI 三者分工与翼型 L/D 对比（cei rei roster，数值见［原文 P01 Table 2］）](../../images/L01_s4_cei_rei_roster_zh.png)

> **指读：** 三人分工——EI 主攻、CEI 守近处、REI 侦远处；右侧比分是后文伏笔。

**(a) CEI — 校准 EI：治瞎逛，强化近处开发**

把尺子从 y_PBS **抬高**到 ξ_Calibrated > y_PBS，重算 z：

**〔式〕** z̃ = (ξ_Calibrated − ŷ(x)) / σ(x)，  CEI(x) = σ(x) (z̃ Φ(z̃) + φ(z̃))

**回译：** 许多原来 z≤0 的点，被抬尺后变成 z̃>0，重新关回"有希望区"。  
再叠加**距离窗** δ₁：只接受落在当前最优点附近的建议（ε < ‖x−x_PBS‖ ≤ d_T 时为 1，ε 常取 0.001 防重复采样）。

**(b) REI — 重校准 EI：治死守小巷，强化远处探索**

**〔式〕** REI(x) = CEI(x) · δ₂(‖x−x_PBS‖)，  δ₂ = 1 − δ₁

**回译：** REI **只**在近处地盘之外取点。δ₁ 与 δ₂ 像两块互补的城区规划——**CEI 管近，REI 管远。**

**(c) 值班经理手册 — CR-EI 调度（原文式 17–18）**

预警线 y_T = 已有样本目标值的**中位数**；计数器 n_Breakthrough 看 EI 是否还在"打破纪录"。

![CR-EI 值班经理手册三分支决策树（schedule tree）](../../images/L01_d_schedule_tree_zh.png)

> **指读：** 从上往下互斥优先。绿：EI 正常只采 EI；黄：有进展则 EI+REI 并行；红：EI 建议点比中位数还差 → 判定瞎逛，改 CEI+REI。

1. n_Breakthrough = 0（EI 正常）→ 只采 EI：  
   **〔式〕** x*_new = {x*_EI}  
2. n_Breakthrough > 0（仍有进展）→ EI 与 REI 并行：  
   **〔式〕** x*_new = {x*_EI, x*_REI}  
3. y(x*_EI) ≥ y_T（疑似瞎逛）→ 改 CEI + REI：  
   **〔式〕** x*_new = {x*_CEI, x*_REI}

**餐厅版回扣：**  
EI 像主探路员；REI 是派去河对岸的侦察兵；一旦主探路员开始在工业区空转（建议点还不如半数已吃过的店），经理立刻把主探路员换成"只准在冠军店附近精耕"的 CEI，同时保留远侦察。

> **一句话记住：** EI 顺就让它跑，同时派 REI 远眺；EI 一瞎逛，就换成 CEI 收近 + REI 保远。

**CEI/REI 餐厅排班表：**  
| 角色 | 地盘 | 一句话 |
| CEI | 冠军店附近 | 抬尺，只精耕有希望区 |
| REI | 河对岸 | 保远方选项，防死守小巷 |
| EI | 全局默认 | 正常时主攻 |
经理看中位数预警线：建议点还不如半数已吃过的店 → 判定瞎逛换班。

#### 5. 实验验证与量化突破

**先报胜负：** 在 7 个基准和翼型工程题上，CR-EI 相对经典 EI 变体，**更快、更稳、更好**。

**算例一：7 个基准函数**（每算法 20 次独立运行；对手 EGO / PEI / GEI / E3I）

| 函数 | EGO | PEI | GEI | E3I | **CR-EI** |
| :--- | :---: | :---: | :---: | :---: | :---: |
| Shekel4 成功率 | 17/20 | 20/20 | 6/20 | 14/20 | **20/20** |
| Trid10 成功率 | 14/20 | 10/20 | 13/20 | 20/20 | **20/20** |

原文结论：**除 10 维 Trid10 外，CR-EI 在其余 6 个基准上均以更快收敛取得最优**［原文 P01 Table 1 / §4.3］。

**算例二：低速翼型（工程级）**

- 参数化：GAN + UIUC 翼型库，**13 维**；  
- 求解器 XFOIL；Re = 1.8×10⁶、Ma = 0.01、AoA = 0°；  
- 目标：最大化升阻比 L/D（实现为最小化 −L/D）；每组 10 次运行。

| 指标 | EGO | PEI | GEI | E3I | **CR-EI** |
| :--- | :---: | :---: | :---: | :---: | :---: |
| 均值 ± 标准差 | −239.34 ± 8.60 | −240.66 ± 6.41 | −240.70 ± 4.57 | −242.20 ± 4.48 | **−246.34 ± 3.56** |
| 中位数 | −241.44 | −242.74 | −240.82 | −241.92 | **−248.09** |

**体感换算（只读两格就够）：**

- 相对 EGO，平均 L/D 提升 **2.92%**［由 Table 2：(246.34−239.34)/239.34］；  
- 标准差 8.60 → 3.56，**离散度降 58.6%**［由 Table 2］——不是"平均好看一点"，而是**十次里次次更稳**。对要签字画押的工程设计，这比均值更救命。

**参数敏感性：** 距离参数 α、incumbent 参数 β。Camel6 / Hartman6 扫描显示 **β = 0.1 综合最优**；β 越大越抗瞎逛，但搜索区膨胀，过大则约束作废［原文 P01 §4.5］。

**翼型工程读法加长：**  
均值更好：平均 L/D 更香。  
标准差下降：十次独立运行更挤在一起——签字要的是可重复，不是一次运气。  
β=0.1 是综合甜点：越大越抗瞎逛，过大搜索区膨胀约束作废［原文 P01 §4.5］。

#### 1. 生活与物理直觉引子：老专家与实习生

想象你经营一家设计公司，手下有两类人：

- **老专家**：画图精准、结论可靠，但**时薪 3000 元，一天只能出 1 张图**；
- **实习生**：速度快、一天能出 10 张图，**时薪 300 元**，但图纸常有偏差，只能看个大概趋势。

现在要做一个设计招标。聪明的做法显然不是"所有图都让老专家画"（太贵），也不是"全让实习生画"（不可靠）。你会让**实习生先铺开画一批，把大致方向摸出来；老专家只在最关键的几张图上出手**。

这就是**多保真优化（Multi-Fidelity Optimization, MFO）**的全部思想。在叶轮机械里：

- **低保真（LF）** = 粗网格 CFD（1.2 万单元）、无粘 Euler、二维简化模型；
- **高保真（HF）** = 细网格 RANS（10 万单元）、三维全环、带转捩模型。

本文的工程算例中，**LF 与 HF 的成本比是 0.1**——也就是说，一次高保真的钱能做十次低保真［原文 P02 §4.3］。

**但这里有个二十年的老问题**：每轮迭代里，到底哪些点该让老专家（HF）看，哪些点交给实习生（LF）？这就是本文所说的 **sample assignment（样本分配）问题**。

**把招标周历摊开看一遍（趣味回扣）：**

| 工作日 | 实习生（LF） | 老专家（HF） | 经理在想什么 |
| :--- | :--- | :--- | :--- |
| 周一 | 狂出 10 张草图 | 休息 | 「先把地形摸出来」 |
| 周二 | 再出 10 张 | 挑 1 张精修 | 「只在苗头处砸钱」 |
| …… | …… | …… | 若没有滤波，专家会被灌进一堆平庸图 |

若没有 Filter 那道门槛，并行批次里会混进大量「GEI 看起来花哨、其实不配见专家」的点——机房灯亮着，智慧在空转。这就是反派**集群空转**。

**周历回扣：** 若无 Filter，并行批会塞满「GEI 花哨但不配见专家」的点——灯亮着，智慧空转。

> **先猜后揭：** 若本讲反派「集群空转」赢了，你的下一笔 CFD/实验预算会怎样被浪费？揭晓贯穿 §3–§5。

| 生活元素 | 工程元素 | 符号 |
| :--- | :--- | :--- |
| 主比喻侧 | 低/高保真 | y_LF/y_HF |
| 主比喻侧 | 缩放因子 | ρ |
| 主比喻侧 | 差异函数 | Z_DF |
| 主比喻侧 | 广义EI/幂次 | GEI,g |

**把「时薪」再算一遍（趣味加长）：**  
若招标只要 30 张「可信图」，全专家贵、全实习险。混合策略的关键不是拍脑袋比例，而是**每一张专家图都对应一个过了门槛的理由**——这正是 T 存在的意义。

**失败剧本：** 经理取消滤波器，「GEI 前 10 名全给专家」。两周后专家工位堆满平庸图，实习生反而闲着。机房利用率很高，**有效学习率**很低。这就是集群空转的生活版。

**招标周的正确打开方式：**  
周一 LF 铺图；门槛决定周二专家看谁；周末对照无滤波是否假快速。  
周历本身就是算法。

#### 2. 叶轮机械中的真实工程死穴：串行加点浪费了整个机房

![parallel timeline 串行空转 vs 并行批墙钟](../../images/L02_d_parallel_timeline_zh.png)

> **指读：** 上条串行等核；下条 HF+LF 同批；空转是调度病。

![串行加点导致集群空转：串行与并行的时间对比（手绘笔记版）](../../images/L02_s2_idle_cluster_zh.png)

> **指读：** 这张图是本讲工程死穴的一张图版本。

传统的多保真 EGO 类算法（如 augmented-EI、VF-EI）有一个共同特征：**每轮迭代只加一个样本**。

问题在两方面：

1. **贵**：一次 CFD 几小时，一个设计周期几百次调用，串行下来是几个月；
2. **浪费**：现代计算集群一晚上能同时跑几十个 CFD 作业，单点串行加点意味着**大部分核在空转**。

同时，已有算法在决定"这个点用 HF 还是 LF"时，往往只看相似性与成本比，**没有利用"LF 模型到底靠不靠谱"这一关键信息**。本文要解决的，正是这两个痛点：**把保真度分配做对，并且一次分配一批**。

**现场感：** 周五下班前组长要数——你面对的不是可以慢慢推的练习题，而是**算错一次就不可回收**的预算。

**串行 vs 并行的时间线（人话）：**  
串行：HF₁ 完成 → 更新模型 → HF₂ → … 墙钟 ≈ n × t_HF。  
并行（本讲）：同一轮抛出 {HF 批, LF 批}，墙钟 ≈ max(t_HF, t_LF)——前提是足够许可证。  
软肋里「并行收益绑许可证」不是抬杠，是工程事实。

**集群空转的两种形态：**  
1) 算法串行加点，核在等；  
2) 算法并行但无 Filter，HF 批次塞满假尖子，核在忙，智慧仍空转。  
第二种更危险，因为利用率报表是绿的，学习曲线却在骗人。

##### 3C. 主路径公式与推导（知识全保留）

**第一步：多保真代理模型 Co-kriging**

把 LF 与 HF 都当成随机过程：
**〔式〕** Y_LF(x) = μ_LF + Z_LF(x), Y_HF(x) = μ_HF + Z_HF(x)

**回译：** 上式是主路径构件——先记住它在算法里负责哪一步，再抠每一个符号。

关键假设是 HF 可以写成"LF 的缩放 + 一个差异函数"：
**〔式〕** y_HF(x) = ρ·y_LF(x) + Z_DF(x)

其中 ρ 是缩放因子，Z_DF 是差异函数（discrepancy function），专门负责刻画"LF 修正后仍与 HF 差多少"。这样，**LF 负责大趋势，DF 负责补差距**，两套高斯过程拼成一个联合协方差矩阵（原文式 4–6）。

**第二步：基线采集函数 GEI（广义期望改善）**

经典 EI 有个毛病：太贪恋当前最优附近。Schonlau（1997）把它推广为带幂次 g 的 GEI：
**〔式〕** E[I(x)^g] = s^g∑_{k=0}^{g}(-1)^kC(g, k)u^{g-k} T_k, u = (f_min-ŷ(x))/(s(x))

**〔式〕** T₀ = Φ(u), T₁ = -φ(u), Tₖ = -u^{k-1} φ(u) + (k-1)T_{k-2}

**g 越大，越偏向全局探索；g=1 时退化为经典 EI。** 取若干个不同的 g，就同时得到一批"有的爱开发、有的爱探索"的候选点——这天然适配并行加点。

**第三步：核心创新——给 GEI 装一个"滤波器"（原文式 10–12）**

定义一个阈值：
**〔式〕** T = ω·y_HF-min + (1-ω)·y_HF-mean

其中 y_HF-min 是当前最优，y_HF-mean 是历史加权平均：
**〔式〕** y_HF-mean = (1)/(iter)∑_{i=0}^{iter}((1)/(nᵢ)∑_{j=1}^{n}_iy_HF-ij)

而权重 ω **由 HF 与 LF 的相关性自适应决定**——这是全文最漂亮的一笔：
**〔式〕** ω = (1)/(1 + (σ̂²_DF/σ̂²_LF)^{0.5})

**物理含义请务必记住：**

- 当 **LF 与 HF 高度相关**时，差异函数 Z_DF 的方差 σ̂²_DF 相对很小 → 分母趋近 1 → **ω→1** → 阈值 T 贴近当前最优值 y_HF-min → **只有非常好（优于 T）的点才配用 HF**，采样极度聚焦于局部开发。
- 当 **LF 与 HF 相关性差**时，σ̂²_DF 大 → ω 变小 → 阈值 T 贴近历史均值 → **HF 的投放区域被放大**，避免在不可信的 LF 引导下钻牛角尖，转而加强全局探索。

**第四步：候选点去重叠**

不同 g 给出的候选点可能重合，直接一起投进 Co-kriging 会让协方差矩阵病态。本文用层次聚类（逐个合并距离最小的一类，直到类间最小距离大于阈值 d_T）把重叠点聚掉。

```
每轮迭代：
  1. 用现有 HF + LF 样本拟合 Co-kriging 代理
  2. 用多个不同 g 的 GEI，生成一批候选点（既含开发点，也含探索点）
  3. 层次聚类去掉重叠候选点
  4. 计算自适应权重 ω = 1/(1+ (σ²_DF/σ²_LF)^0.5 )
  5. 计算阈值 T = ω·y_HF-min + (1-ω)·y_HF-mean
  6. 分流：
       预测值优于 T 的候选点  → 送 HF 仿真（贵，但值得）
       其余候选点            → 送 LF 仿真（便宜，用于全局探索+降不确定性）
  7. 一批 HF 与一批 LF 样本同时提交，并行计算

```

> **一句话记住**：**GEI 负责"去哪儿采"，滤波器负责"花多少钱采"。**

**主比喻回扣：** 把上面的分支再翻译成「设计公司：老专家 vs 实习生」——若某步在生活里说不通，多半是符号没对齐。

**并行批的现场约束清单：**  
- 许可证 ≥ 批大小？否则自动降批。  
- LF/HF 网格与求解器队列是否两条线？  
- 相关 ω 是否每轮重算，还是冻结了过期相关？  
门槛 T 在许可证不足时**仍然值钱**：它决定稀缺的 HF 名额给谁。

- **GEI 只用了 8 次迭代就"收敛"了，但收敛到的是最差的最优值 2.760**——没有滤波器时，HF 被挥霍在不太有希望的点上，看似快，实则跑偏。

**账本精读（再钉一次）：**  
无滤波 GEI：迭代 8，最优 2.760（差）。Filter-GEI：迭代 13，最优 2.720（好）。  
慢 5 轮迭代，换的是**不跑偏**。相对串行 36–51 轮仍是断崖优势。读表先问「快是真快还是假快」。

**可以攻击的点：**

1. **"并行"是算法层面的并行，实验是串行模拟的**。真拿到工程现场，收益取决于你有多少个 CFD 许可证/核；很多单位恰恰卡在许可证数量上。
2. **成本比没有进入公式**。ω 只用了方差比 σ̂²_DF/σ̂²_LF，**没有把 LF/HF 的实际成本比纳入**。本文工程算例的成本比恰好是 0.1；若 LF 也很贵（成本比接近 1），多投 LF 的滤波策略就不一定划算了。
3. **阈值与权重的启发式本质**。T 取"最优值与加权均值的凸组合"缺乏最优性证明；ω 的自适应也只有定性论证。
4. **维数量级有限**：基准最高 6 维，工程算例 7 维。真正的多级叶栅是 100+ 维（见**论文 07**），Co-kriging 在高维下的建模能力本身就是瓶颈。
5. **隐含前提"LF 大体能捕捉 HF 趋势"**。一旦这个前提在某块区域失效，滤波器反而会把 HF 集中投到被 LF 误导的区域——这正是**论文 13（EMFS / MSFO）**要处理的问题。

**承前：** 建立在 Co-kriging（Forrester et al. 2007）与 GEI（Schonlau 1997）之上，思想直接继承自同组前作 **论文 01（CR-EI）**——"用一个自适应指标来决定这一轮怎么采样"。

**启后：**
- **论文 13（EMFS / MSFO）**：正面处理"LF 在某些区域反而误导优化"的场景，用 DBSCAN 找出多保真代理建不准的区域，在那里改建单保真代理；
- **论文 07（GSDE）**：把优化从"低维多保真 + 贝叶斯"推进到"126 维 + 代理辅助进化"；
- **论文 11（DA-EGO）**：把"自适应分配"从**保真度维度**迁移到**子空间维度**。

#### 附：并行加点的许可证现实

算法说「一批 HF + 一批 LF」时，现场常卡在：

- CFD 许可证数 < 批大小；  
- 队列策略把并行拆回串行；  
- LF 与 HF 网格流程不共享，调度摩擦大。

**所以 §6 软肋不是抬杠：** 并行收益是「算法可达上限 × 许可证可达上限」的乘积。Filter 仍值得做——即使批变小，**门槛 T 依然决定谁配见专家**。

#### 1. 生活与物理直觉引子：为什么不能"一排叶片一排叶片地优化"

![team formation 7 排叶片必须一起练](../../images/L03_d_team_formation_zh.png)

> **指读：** 排间传球（尾迹/旋流）改了，单排最优作废。

先建立一个物理直觉。**压气机不是一个叶片在战斗，而是一支队伍在战斗。**

空气从第 1 排叶片流过时，会在出口留下"尾迹"和"旋流"；第 2 排叶片吃到的，正是被第 1 排搅过的气流。如果你把第 1 排单独优化到极限，第 2 排的进口条件就变了，它的最优形状也随之改变——反过来又影响第 1 排。

这就是为什么原文强调：**为充分考虑叶片排与级之间的相互作用，两级以上的叶栅必须同时优化**［原文 P07 摘要］。

代价是变量数的爆炸。先把**被计数的对象**钉死，再谈算法——否则「18 维」「126 维」只是口号。

**① 几何对象**［原文 P07 §Geometry definition / Blade parameterization］

- 一台 **3.5 级**压气机：进口导叶 **S0** + 三个低压级 **R1/S1、R2/S2、R3/S3**，共 **7 排叶片**。
- **级 ≠ 排**：一对「转子+静子」常称一级；此处 3.5 级 = 1 排导叶 + 3 个完整级，排数跟原文，不靠常识瞎加。
- 优化对象是各排叶片的三维形状（NURBS 截面 + 积叠），7 排**同时**进同一个设计向量。

**② 单排 18 维怎么来？**（计数单位 = 优化器接收的**独立标量**，不是图上的点数）［原文 P07 Blade parameterization；Table 2］

> **口径警告：** 控制点是几何操纵对象；**设计变量**才是维数。一点可以固定（0 维）、只沿法向动（1 维）、或不进优化向量。

| 块 | 原文设定 | 独立标量 |
| :--- | :--- | ---: |
| 截面 | 根 / 中 / 尖 共 3 个二维截面，蒙皮成三维叶片 | — |
| 只动哪面 | **只调吸力面**（压力面不动）［原文］ | — |
| 每截面控制点 | 吸力面 **7** 点：前缘、尾缘**固定**；其余 **5** 点沿拟合曲线**法向**主动移动；每点 **1** 标量 | 3×5 = **15** |
| 积叠（弯/掠） | **中**截面**周向**平移 1 + **尖**截面**周向**平移 1 + **尖**截面**轴向**平移 1 | **3** |
| **单排合计** | 原文：*18 design variables … each blade* | **15+3 = 18** |

旧讲义曾缩写成「根/中/尖各 5 点 + 周向平移 + 轴向平移」，字面 5×3+1+1=**17≠18**——是把 **3 个积叠标量**收成两个词的**转述错误**，不是原文少一维。已按 PDF 纠正。

**③ 整机 126 维**

原文直接写明：7 排 × 每排 18 = **126** 个设计变量（**名义**输入维）［原文 P07 Blade parameterization / 摘要 *126 variables*］。  
乘法前提（原文均满足）：7 排都优化、每排同构 18、无跨排共享、此处未改报「有效自由度」。

**〔式〕** 单排 18（标量）× 7 排 = **126 维**名义设计空间［原文 P07］

而一个设计周期里，你**只负担得起几百到几千次 CFD**［原文 P07 摘要］。126 维里撒 1000 个点，平均每维约 1000^(1/126)≈1.056 份——**比「每个方向一分为二」还稀**。

这就是所谓**高维昂贵黑箱（High-dimensional Expensive Black-box, HEB）**问题。

**量级感再钉一根钉子：**

一次 3.5 级压气机 CFD ≈ **1–1.5 小时**［原文 P07］。  
DE 要两万次量级，就是两个月量级的墙钟时间；GSDE 用约 1500 次，大约一周。  
你不是在省「几次点击」，你是在省**工程师的整个季度**。

队伍比喻回扣：第 1 排改理想、第 2 排入口就变了——**单独优化每一排，在物理上就是做错题**。

**量级钉：** 单次CFD约1–1.5小时。DE两月，GSDE约一周——省的是工程师的季度。

| 主比喻侧 | 种群 | N |

**队伍训练的反例：**  
「先把第 1 排优化到头再冻住」像让前锋单练冲顶却不让中场传球——进口边界一变，单排最优作废。两级以上必须同时优化，是流动耦合硬约束［原文 P07 摘要］。

**126 维体感：** 想「7 个人各 18 个动作要领，同一套战术」；代理是陪练，CFD 是正式出场次数。

**126 维的第二个类比：**  
不是 126 个独立旋钮，而是 7 排叶片的联合战术板。  
改第 1 排出口，第 2 排进口边界条件改写——单独最优是物理错题。  
GSDE 用 RBF+DE 紧耦合，是因为 GP 在这个维度上先失明。

**队伍战术板（加长）：**  
7 排叶片像 7 个位置：前锋的冲顶依赖中场传球角度。  
你把第 1 排「优化到头」并冻结，等于让前锋在错误传球线路上练一百次——第 2 排进口旋流一变，单排最优当场作废。  
原文坚持两级以上必须同时优化，不是方法论偏好，是流动耦合的硬约束［原文 P07 摘要］。

**126 维的第三个体感：**  
1000 个点摊在 126 维，每个方向约 1000^(1/126)≈1.056 份——连「一分为二」都做不到。  
这时还问 GP「哪里不确定」，答案本身就不可信。

#### 2. 叶轮机械中的真实工程死穴：高斯过程在高维下会"失明"

![高斯过程在高维下的四个软肋与 GSDE 的路线选择（kriging blind in high dim，手绘笔记版）](../../images/L03_s2_kriging_blind_zh.png)

> **指读：** 这张图是本讲工程死穴的一张图版本。

第 01 讲的 CR-EI、第 02 讲的 Filter-GEI 都建立在**高斯过程（Kriging）**之上。它们很优雅，但有个致命的软肋：

| 问题 | 后果 |
| :--- | :--- |
| GP 的协方差矩阵随样本数 n 呈 O(n³) 增长 | 样本上千就非常慢 |
| 高维下核函数的长度尺度难以估计 | 代理模型拟合失真 |
| 高维下"距离"失去区分度（距离集中效应） | "哪里不确定"这件事本身就不确定了 |
| EI 类采集函数需要在整个空间上全局最大化 | 高维下这个子优化本身就很难 |

所以本文做了一个**路线选择**：**放弃贝叶斯优化框架，改用进化算法（差分进化 DE）打底，把代理模型作为"局部搜索加速器"嵌入进去。** 这就是 GSDE（Generalized Surrogate-assisted Differential Evolution）。

**现场感：** 周五下班前组长要数——你面对的不是可以慢慢推的练习题，而是**算错一次就不可回收**的预算。

**为何 GSDE「不时髦也选 RBF」：** GP 的 O(n³)、高维核长度尺度、距离集中、EI 子优化——四只钉子。RBF 一次解线性系，是工程上的少即是多。

**GP 四软肋 → GSDE 四对策（对照表）：**

| GP 软肋 | 后果 | GSDE 对策 |
| :--- | :--- | :--- |
| O(n³) 协方差 | 样本上千训练炸 | 局部 RBF，一次解线性系 |
| 高维长度尺度难估 | 拟合失真 | 不抠核超参，橡胶膜直接铺 |
| 距离集中 | 「不确定在哪」失效 | 代理嵌入 DE 生成基因，不靠全局 EI 寻峰 |
| EI 子优化也难 | 采集函数本身卡死 | 进化 + 有限真 CFD 名额 |

选 RBF 不是赶时髦，是工程上的少即是多。

##### 3C. 主路径公式与推导（知识全保留）

**第一步：为什么代理模型换成 RBF**

原文指出：在高维设计空间，RBF 的预测精度强于其他常见代理，且训练时间随变量数增长仍可接受。GSDE 采用**三次 RBF + 线性多项式尾项**：
**〔式〕** f̂(x_new) = ∑_{i=1}^{n}λᵢ φ(‖x_new-xᵢ‖) + p(x_new)

**回译：** 上式是主路径构件——先记住它在算法里负责哪一步，再抠每一个符号。

**〔式〕** φ(r) = r³, p(x) = ∑_{i=1}^{D} b_i xᵢ + a

待定系数共 n+D+1 个（λ₁…λ_n, b₁…b_D, a），由一个线性方程组**一次性解出**（不需要迭代优化超参数，这正是 RBF 在高维工程场景的实用之处）：

分块线性系统 Φλ + Pc = F，P^T λ = 0，其中核矩阵 Φ_ij = φ(‖x_i − x_j‖)，P 为多项式基矩阵，λ 与 c 为待定系数。

**第二步：策略一——代理引导的差分进化（GSDE 的核心）**

经典 DE 的 best/1 变异是：
**〔式〕** vᵢ = x_best + F(xᵣ₁-xᵣ₂), N = 50, F = 0.3 （默认）

GSDE 的关键改动是**给每个父代点 xᵢ 建一个局部 RBF**：

- 训练点取距 xᵢ 最近的 5× D 个样本（126 维时即 630 个）；
- 局部区域半径**自适应**：

**〔式〕** rᵢ = 0.5 D_{i,max}√\[D\]((N-1)/(D))

其中 Dᵢ,max 是 xᵢ 到其他父代点的最大距离——**维数 D 越高，这个根式越接近 1，半径越大**，这正是对高维稀疏性的补偿；
- 用 PSO（种群 50、迭代 100 次）在这个局部 RBF 上找出**预测父点** xᵢ^*。

然后做**指数交叉**，把变异点与预测父点缝合成候选个体：

二项式交叉（默认 CR=0.9）：从随机维 j_rand 起，若 rand[0,1] ≤ CR 则取试验分量 v_i,j，否则保留预测父点分量 x*_i,j，记作 
**〔式〕** uᵢ = Crossover(vᵢ, x*ᵢ; CR = 0.9)

> **请特别注意这里的设计哲学**：在传统"DE + 代理"的松散耦合里，代理模型只用来**筛选**已经生成的候选点；而在 GSDE 里，代理模型**直接参与生成子代的基因**——xᵢ^* 的某些维度会直接进入下一代。原文说得很明确：这种"紧耦合（tight form）"正是 GSDE 在高维下仍能表现良好的特殊之处［原文 P07 §Proposed algorithm］。

**第三步：策略二——基于父代的选择（省下真金白银）**

每轮生成的候选点如果全做 CFD，开销受不了。GSDE 的办法是：**按父代适应度给候选点排序，只挑前 T=9 个去做真实 CFD**。理由是"优秀父代产生的子代更可能携带好基因"。这 9 个子代随后替换父代中最差的 9 个点。

**第四步：策略三——基于代理的局部搜索（并行进行）**

在当前最优点 x_best 附近再建一个局部 RBF，用 PSO 找局部最优：
**〔式〕** x* = argmin f̂_RBF(x), x ∈ [x_best-Δ, x_best + Δ]∩[lb, ub]

其中 Δ 取"x_best 到训练点中适应度最差者距离"的一半。若 x* 优于 x_best 就替换它。

**这三条策略是并行执行的**——这是 GSDE 适配真实计算集群的工程设计。

#### 4. 算法控制流

![factory stations GSDE 三工位并行](../../images/L03_d_factory_stations_zh.png)

> **指读：** ①局部RBF出预测父点 ②父代优选只送有限真CFD ③最优点附近局部搜索——三路并行。

> 🧭 **值班手册：** 先看「什么情况下走哪条分支」，公式是对白速记不是主角。

```

初始化：采样 → 建 RBF 代理
每轮迭代（三路并行）：
  ① 代理引导差分进化
       对每个父点 xi：
          局部 RBF（5D 个最近邻点，半径 ri 自适应）
          PSO 在局部 RBF 上求预测父点 xi*
          best/1 变异 vi = x_best + F(x_r1 - x_r2)
          指数交叉 vi 与 xi* → 候选 ui
  ② 基于父代的选择
          按父代适应度给所有 ui 排序，只取前 T=9 个送真实 CFD
          用这 9 个子代替换父代中最差的 9 个
  ③ 基于代理的局部搜索（并行）
          在 x_best 附近建局部 RBF，PSO 求 x*，优于 x_best 则替换

```

> **一句话记住：** 高维别硬上 Kriging；进阶：RBF 像橡胶膜，一次解线性系统。

**主比喻回扣：** 把上面的分支再翻译成「多排叶片是一支必须一起训练的队伍」——若某步在生活里说不通，多半是符号没对齐。

**三工位并行的集群含义：**  
工位①生成候选基因；工位②只让前 T 个做真 CFD；工位③在精英附近局部挖。  
墙钟接近「最慢工位」，而不是三工位串行相加——前提是许可证与队列允许。  
**回扣：** 维数灾难的解药不只是数学，也是调度。

**可以攻击的点**（以下为本文方法层面的合理质疑，涉及的设置参数均出自原文 P07 §Proposed algorithm）：

1. **只在设计点优化**。现代压气机要求在整个工作线（近失速到近堵塞）上都达标，单点优化得到的叶片很可能在非设计点恶化——本文未做多点优化。
2. **超参数多且缺乏敏感性分析**。N=50, F=0.3, CR=0.9, T=9, 5D 训练集、PSO(50×100) 基本都是默认值，原文没有报告它们对结果的影响［原文 P07 参数设置段：种群规模取 50 以平衡精度与开销，F=0.3、CR=0.9、局部训练集 5D］。
3. **局部 RBF 在高维下的"局部性"存疑**。取 5D=630 个"最近邻"点，在 126 维空间里，最近邻与最远邻的距离差距会因距离集中效应而急剧缩小，"局部"可能已经不再局部。

5. **气动机理是后验解释**，没有提炼成可迁移的设计准则（例如"转子前掠多少度能改善多少"）。
   ［以上第 1–5 点均基于原文 P07 报告的方法设置与结果所作的合理质疑；其中 N=50、F=0.3、CR=0.9、T=9、5D 训练集、PSO(50×100) 等参数出自 §Proposed algorithm］

#### 1. 生活与物理直觉引子：为什么"分而治之"在优化里这么难

先讲一个生活场景。你要装修一套 126 个房间的超大房子，预算只够请设计师做 **1000 次**方案评审。

**笨办法**：每次都让设计师把整套房子从头到尾重新设计一遍。1000 次下来，每个房间平均只被认真推敲过 8 次——大概率烂尾。

**聪明办法**：把房子按功能分区（客厅区、卧室区、厨卫区……），**每次集中精力改一个区**，其他区保持现状；改完一个区就把它的最优方案"固化"下来，再改下一个区；改完一轮后重新审视：**哪些区之间其实互相影响**（比如开放式厨房和客厅必须一起改），把它们合并后重新规划。

这就是 DA-EGO 的核心思路。但这里有个真正的难点，也是本文的贡献所在：

> **你事先并不知道哪些房间之间互相影响。**

在叶轮机械里，这个"影响"是物理上真实存在的：改动第 1 排叶片，会改变第 2 排的进口气流角，于是第 1 排和第 2 排的变量之间存在**交互作用（interaction）**。把它们拆进不同子空间各自优化，就会得到互相矛盾的结果。

所以 DA-EGO 的关键不是"分解"，而是"**动态**分解"——**每轮迭代都重新判断谁和谁该分在一起**。

**装修监理的口令：**

- 水电墙（强交互）→ 绝不能拆到两个标段；  
- 两间不相干的客房（可分离）→ 可以轮流施工；  
- 疑似承重墙（P_S）→ 先小范围验证，再决定打不打通。

DA-EGO 的「动态」两个字，意思是：**标段划分会随着你对新房结构的理解而改**，不是一锤子合同。

**监理口令：** 水电墙不拆标段；客房可轮流；疑似承重先验。

> **先猜后揭：** 若本讲反派「假交互」赢了，你的下一笔 CFD/实验预算会怎样被浪费？揭晓贯穿 §3–§5。

| 生活元素 | 工程元素 | 符号 |
| :--- | :--- | :--- |
| 主比喻侧 | 交互分 | SPCE_ij |
| 主比喻侧 | 确认/疑似 | P_C/P_S |
| 主比喻侧 | 变量子集 | 子空间 |
| 主比喻侧 | 精英拼回 | 聚合 |

**装修事故集：** 承重墙拆进两个包工队→返工；客房绑死同一工期→浪费并行。交互分数就是给每面墙打「能否拆标段」的分。

**假交互的两种事故：**  
- 把强交互拆进两个包工队 → 返工（假可分离）。  
- 把弱交互绑死同一工期 → 浪费并行（假必须同屋）。  
交互分数 + P_C/P_S 就是给每面墙打「能否拆标段」的监理报告。

**装修监理的一天：**  
上午：水电墙（强交互）被拆进两个标段，下午返工。  
傍晚：客房（弱交互）被绑死同一工期，并行度浪费。  
DA-EGO 的交互分数，就是自动出具「这面墙能不能拆标段」的报告；P_C 绑死，P_S 疑似先验。

#### 2. 叶轮机械中的真实工程死穴：GSDE 的代价与贝叶斯框架的"不甘心"

![EGO 在低维与高维的取舍，及 DA-EGO 的分解思路（rotor37 divide，手绘笔记版）](../../images/L04_s2_rotor37_divide_zh.png)

> **指读：** 这张图是本讲工程死穴的一张图版本。

第 03 讲的 GSDE 用进化算法硬扛 126 维，效果很好，但它放弃了贝叶斯优化（EGO）这套东西。站在贝叶斯阵营看，这是有遗憾的：

- EGO/Kriging 的**样本效率**在**低维**问题上其实远高于进化算法——几十次评估就能逼近最优；
- 它失效的地方是**高维**：Kriging 建模失真、采集函数全局最优化本身变成难题。

于是问题变成：**能不能不动 EGO 的骨架，只把"高维"这件事解决掉？**

本文给出的答案是：**把高维问题分解成若干低维子问题，在每个子问题上用 EGO 好好优化，再把各子空间学到的知识聚合回全空间。** 而且——**分解方案每轮迭代都要更新**。

原文定义的问题规模是 **d≥ 30 的高维昂贵黑箱问题**［原文 P11 摘要］。

**现场感：** 周五下班前组长要数——你面对的不是可以慢慢推的练习题，而是**算错一次就不可回收**的预算。

**GSDE 已能扛 126 维，为何还要 DA-EGO？**  
因为有人仍想保留贝叶斯的不确定度叙事与 EI 族工具。  
DA-EGO 的回答：不换队伍，换场地——把高维切成可 EGO 的子空间，再聚合精英。  
两条路线不是站队，是工具箱里的两种扳手。

##### 3C. 主路径公式与推导（知识全保留）

**第一步：什么是"变量交互"（interaction）**

设目标函数 f(x)。若变量 x_i 的取值会**改变** x_j 对 f 的影响，则称 x_i 与 x_j 存在交互。

用方差分析（ANOVA）的语言说：把 f 分解成主效应项与交互效应项
**〔式〕** f(x) = f₀ + ∑ᵢ fᵢ(xᵢ) + ∑_{i<j} f_ij(xᵢ, xⱼ) + ⋯

**回译：** 上式是主路径构件——先记住它在算法里负责哪一步，再抠每一个符号。

若 f_ij ≡ 0，则 x_i 与 x_j **可分离**，可以安全地分进不同子空间；反之必须放在同一个子空间里一起优化。

**第二步：怎么在只有稀疏样本时判断交互？——PCE 灵敏度系数**

本文用**多项式混沌展开（PCE）**的灵敏度系数 SPCE_ij 给每一对变量 (x_i, x_j) 打分。D 个变量共有

**〔式〕** (D(D-1))/(2)

个变量对（126 维时是 7875 对）。DA-EGO 把它们分成三类［原文 P11 §3.2.1］：

| 类别 | 记号 | 含义 |
| :--- | :--- | :--- |
| 确认交互 | P_C | 已由低维代理模型验证确认有交互的 t 对 |
| 疑似交互 | P_S | 在剩余变量对中 SPCE_ij 最高的一批，**待验证** |
| 非交互 | — | 其余（可能交互很弱） |

> **原文自己给出的警告（务必记住）**："由于维数灾难的存在，**高维 PCE 代理的精度有限，这会导致交互变量对的选取出现误差**。" 正因如此，P_S 中的疑似交互还要**再用低维代理模型验证确认**。

**第三步：精英点（elite-point）——子空间与全空间之间的知识桥梁**

取全部已评估样本中的**当前最优样本**作为精英点。各子空间优化得到的最优解被**组合进精英点**，再用于全空间的全局搜索。

这一步的意义是：子空间是低维的、好优化的，但它只是"局部视野"；精英点把各局部视野的最优解**拼装成一个全局可行解**，保证子空间优化不会跑偏到全空间的劣解上去。

**第四步：三类知识构成闭环**

原文把"设计空间的知识"明确定义为三类数据［原文 P11 §3］：

1. **采样数据**：所有已评估样本的坐标与函数值；
2. **变量交互关系**：已发现（确认/疑似）的交互变量对；
3. **搜索边界**：每个变量当前的搜索范围。

由此形成闭环：

```

[知识] → 构造子任务（分解方案 + 搜索范围）
            ↓
     各子空间独立做基于代理的优化
            ↓
   子任务数据挖掘（摄动法 + ANOVA 检测交互）
            ↓
[知识更新] → 下一轮的分解方案与搜索范围

```

**第五步：搜索范围收缩**

若此前求解过**相似子任务**（变量相同、精英点不同），则可依据累积经验缩小子问题的搜索范围，从而同时提升优化效率与交互分析的精度［原文 P11 §3.2.2］。

#### 1. 生活与物理直觉引子：老专家带的实习生，也会把你带沟里

> **实习生的判断，大体上是对的。**

如果这个前提不成立呢？想象一下：实习生看图纸有个**系统性偏差**——他总把某种特定结构画得比实际更结实。在设计的早期，这个偏差无所谓，因为大方向是对的；但当设计推进到精细阶段、你已经逼近最优解时，**这个系统性偏差会把你往错误的方向一直带**。

> 多保真优化（MFO）**并不总是**优于单保真优化。在优化的后期，随着高保真样本不断积累，低保真样本会产生**负面效果，误导优化搜索**。［原文 P13 摘要］

##### 3C. 主路径公式与推导（知识全保留）

**第一步：把"多保真为什么失效"写清楚**

多保真代理（以 Co-kriging 为例，参见第 02 讲）把 HF 建模为

**〔式〕** y_HF(x) = ρ·y_LF(x) + Z_DF(x)

**回译：** 上式是主路径构件——先记住它在算法里负责哪一步，再抠每一个符号。

其中 Z_DF 是差异函数（discrepancy function），负责修正 LF 的系统性偏差。

问题在于：**Z_DF 本身也是用有限样本拟合出来的高斯过程**。当 HF 样本在优化后期**高度聚集于当前最优附近**时，Z_DF 在"你真正关心的那块区域"里的估计反而可能很不准——因为 LF 在那里从来就没被 HF 校验过。

于是出现了本文说的现象：**在 MFS 建不准的那块区域，MFS 反而不如一个纯用 HF 建的单保真代理（SFS）。**

**第二步：核心思想——不是"全用 MFS"或"全用 SFS"，而是"哪里 MFS 不行，哪里就换 SFS"**

本文的做法可以概括成一句话：

> 用 **DBSCAN 密度聚类**找出"MFS 建不准"的区域，在该区域**局部改建一个单保真代理（local SFS）**，再用**自适应权重**把 MFS 与这个局部 SFS 融合成一个集成代理 **EMFS**（Ensemble weighted Multi-Fidelity Surrogate）。［原文 P13 摘要］

**第三步：为什么用 DBSCAN 而不是别的聚类？**

DBSCAN（Density-Based Spatial Clustering of Applications with Noise）的特点是：

- **不需要预先指定簇的个数**——你事先并不知道有几个"失真区"；
- **能识别噪声点**——稀疏的离群样本不会被硬塞进某个簇；
- **能发现任意形状的簇**——失真区的几何形状未必是凸的。

这三点恰好契合"找出代理模型失真区域"这个任务：失真区可能不止一个、形状不规则、且边界处样本稀疏。

> 📌 **DBSCAN 的具体参数（邻域半径 ε、最小样本数 MinPts）与自适应权重的具体公式，摘要未给出，原文未获取，本讲不作推测。**

**第四步：命名规范（旧版白皮书在这里错了，必须纠正）**

| 名称 | 全称 | 指代对象 |
| :--- | :--- | :--- |
| **EMFS** | Ensemble weighted Multi-Fidelity Surrogate | **代理模型**：MFS 与局部 SFS 的自适应加权集成体 |
| **MSFO** | Multi- and Single-fidelity surrogate fused Optimization | **优化算法**：用 EMFS 引导搜索的完整算法 |

> ❌ 旧版白皮书第 05 讲的标题写作"**EMFS 算法**：DBSCAN 空间聚类识别失真区的多保真局部融合"，把**代理模型的名字当成了算法名**。
> ✅ 正确表述：**EMFS 是代理模型，MSFO 才是优化算法。**

#### 4. 算法控制流

![EMFS duty 后期假优验尸值班流程](../../images/L05_d_emfs_duty_zh.png)

> **指读：** 画曲线→找交叉→DBSCAN圈团→团内SFS→融合。与 Filter 串联而非二选一。

> 🧭 **值班手册：** 先看「什么情况下走哪条分支」，公式是对白速记不是主角。

依据摘要可确认的流程骨架（**细节参数原文未获取**）：

```

每轮迭代：
  1. 用现有 HF + LF 样本建立多保真代理 MFS（如 Co-kriging）
  2. 用 DBSCAN 对样本/设计空间做密度聚类，
     侦测出 "MFS 在该区域建不准" 的区域
  3. 在这些失真区域内，仅用 HF 样本建立一个局部单保真代理 local SFS
  4. 用自适应权重把 MFS 与 local SFS 融合为集成代理 EMFS
  5. 用 EMFS 引导下一轮加点（这就是 MSFO 算法）

```

> 一句话记住：**不是"多保真 vs 单保真"的二选一，而是"哪里可信就用哪套"的自适应切换。**

**主比喻回扣：** 把上面的分支再翻译成「专家盯过的区，实习生反而开始系统性撒谎」——若某步在生活里说不通，多半是符号没对齐。

**融合口令：** 失准区专家说了算（SFS）；其余区仍可 MFS。权重问「这片区最近谁在撒谎」。

**EMFS 排班：**  
全局仍可用 MFS 探路；DBSCAN 圈出的失准团改 SFS；融合权重看「这片区谁在撒谎」。  
与 Filter 串联：先分配谁见专家，再验尸专家盯过的区。

**EMFS 与 Filter 的串联脚本：**  
每 10 轮：更新 MFS/SFS 曲线。  
发现交叉：启动 DBSCAN 圈失准团。  
团内：SFS 说了算；团外：MFS 仍可探路。  
融合后再跑，看交叉是否消失；不消失则检查 LF 是否结构性失效（不是聚类能救）。

**可以攻击的点：**

1. **"失真区"的判定标准本身依赖代理模型**。用 MFS 去判断"MFS 在哪不准"，存在自我指涉的风险；判定失准时会连锁出错。
2. **DBSCAN 的参数敏感性**。密度聚类对邻域半径与最小样本数非常敏感，而这两个参数与"代理模型误差阈值"之间并无直接的物理换算关系——调参很大程度上靠试。
3. **局部 SFS 的样本从哪里来**？失真区之所以失真，恰恰是因为那里 HF 样本稀少；在 HF 样本稀少的区域建单保真代理，可能同样不可靠。原文未提供此处的处理细节（原文未获取）。
4. **权重的自适应规则缺少理论依据**（原文未获取，无法评价）。
5. **仅两个算例**，且都为该课题组的常规算例，未在更广泛的基准上验证泛化性。

**承前：**
- 直接**修正了第 02 讲（Filter-GEI）的隐含前提**。Filter-GEI 假定"LF 大体能捕捉 HF 趋势"，并据此设计滤波阈值；本文则处理**这个前提在局部失效**的情形。两篇论文构成"多保真方法"的一体两面。
- 方法上继承了 Co-kriging 与多保真 EGO 的体系。

**启后：**
- **论文 07（GSDE）与论文 11（DA-EGO）**：如果说 EMFS 处理的是"**保真度维度**上的模型不可信"，那么 GSDE 与 DA-EGO 处理的是"**维度灾难**带来的模型不可信"。三者共享同一个哲学——**先识别代理模型在哪里不可信，再在那里换一种策略**。
