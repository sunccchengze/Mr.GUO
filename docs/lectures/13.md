#### 1. 生活与物理直觉引子：赢了比赛，却说不清为什么赢

想象一位厨师参加厨艺大赛，拿了冠军。记者问他："你这道菜为什么好吃？"

如果他说"因为我放了很多调料，炒了很久"——这不算回答。真正有价值的回答是：

> "关键是**糖要在下酱油之前放**，这样能裹住肉的水分；至于火候，前两分钟必须大火，之后转小火——**这两个步骤顺序反了就会柴**。"

前十二讲，我们一直在研究**"怎么更快找到冠军"**——CR-EI、Filter-GEI、GSDE、DA-EGO、KT-ASO、GTO、TNO……每一讲都在让搜索更高效。

但这一讲要问一个**被忽略的问题**：

> **找到最优解之后，我们能说清"它为什么好吗"？**

要知道，一次优化跑下来会产生几百上千个样本（几何 + CFD 结果）。这些数据的价值**绝不只是"里面有一个最优解"**——它们记录了整个设计空间的"地形"。可惜大多数时候，我们只取走最高点，然后把地图扔了。

本文要做的事：**把这张地图读出来，变成人能理解的设计准则。**

**归因不是事后诸葛：**  
优化日志里躺着上百次 CFD，若只交出一个冠军外形，工程师无法写进设计手册。  
SHAP 要的是：**可执行的句子**——例如「尾缘半径别乱加厚」。

**手册测试：** 这句能写进设计规范吗？


> **先猜后揭：** 若本讲反派「冠军无配方」赢了，你的下一笔 CFD/实验预算会怎样被浪费？揭晓贯穿 §3–§5。


| 生活元素 | 工程元素 | 符号 |
| :--- | :--- | :--- |
| 主比喻侧 | SHAP值 | φ_i |
| 主比喻侧 | 可执行句 | 准则 |
| 主比喻侧 | 设计变量 | 93维 |


**厨房验收：** 只给总分则菜谱无法复现。SHAP 拆贡献；准则卡写成可检查区间，才能进岗位手册。

**颁奖典礼翻车：**  
优化组捧出冠军叶型，规范组问「写哪三条」。全场沉默。  
外形图不能进手册；**可检查区间**才能进手册。SHAP 是把沉默变成句子的翻译器——它翻译的是贡献，不是因果神谕。

**颁奖典礼加长版：**  
优化组：外形来了。  
规范组：写哪三条？  
工艺组：这条敏感方向铣不出来。  
强度组：那条和圆角耦合。  
SHAP 提供的是**优先调查清单**；准则卡是跨组谈判后的可执行句子。  
把 SHAP 当因果神谕，会在下一轮数据上丢脸。

##### 3C. 主路径公式与推导（知识全保留）

**第一步：SHAP 的思想——公平的"分功劳"**

一场篮球赛赢了 20 分，五个球员各自贡献多少？

朴素算法会看"谁在场时球队得分高"，但这有偏——因为球员是**组合**出场的。合作博弈论给出的公平分配方案叫 **Shapley 值**，做法是：

> 枚举**所有可能的出场组合**，计算某球员加入每个组合时带来的**边际贡献**，再对所有组合做加权平均。

把"球员"换成"设计变量"、"比赛得分"换成"模型预测值"，就是 **SHAP（SHapley Additive exPlanations）**。

**第二步：SHAP 的严格定义**
**〔式〕** φᵢ = ∑_S⊆N∖{i}(|S|! (M-|S|-1)!)/(M!)[f_x(S∪{i})-f_x(S)]

**回译：** 上式是主路径构件——先记住它在算法里负责哪一步，再抠每一个符号。


- N=1,2,…,M：全部特征的下标集，M 为特征总数；
- S：不含特征 i 的任意子集；
- fx(Scupi)-fx(S)：**特征 i 在子集 S 下的边际贡献**；
- 前面的阶乘系数：对所有子集大小做**公平加权**。

**第三步：SHAP 的可加性（这是它最实用的性质）**
**〔式〕** yᵢ = y_base + f(xᵢ1) + f(xᵢ2) + ⋯ + f(x_ik)


其中 y_base 通常是全体样本目标变量的**均值**（"平均水平"）。

- f(xᵢj)>0：该特征**推高**了预测值（对效率是正面作用）；
- f(xᵢj)<0：该特征**拉低**了预测值。

**这个性质意味着什么？** 意味着你可以把任意一次预测**精确地拆成"各个变量贡献了多少"的账本**——而且账目必须配平。这对工程师来说极其直观。

**第四步：为什么用 XGBoost 当被解释的模型？**

SHAP 需要一个"被解释的模型"。本文用 **XGBoost**：
**〔式〕** ŷᵢ^(t) = ŷᵢ^(t-1) + fₜ(xᵢ), Obj = ∑ᵢ l(yᵢ, ŷᵢ) + ∑ₖΩ(fₖ)


- 串行集成决策树，每轮拟合上一轮的**残差**；
- 目标函数 = **损失函数 + 正则项**（防过拟合）；
- 树模型天然支持高效的 SHAP 精确计算（TreeSHAP）。

本文 XGBoost 的精度：交叉验证 **RMSE = 0.0290%**，**相对误差 = 0.0274%**［§4.2］。

**第五步：本文的方法论创新——把 SHAP 从 0 维推到 1 维和 2 维**

这是本讲最值得记住的贡献：

| 层次 | 数据形态 | 能回答的问题 |
| :--- | :--- | :--- |
| **0 维** | 标量输出（级效率） | 哪些变量重要？**调大还是调小好**？ |
| **1 维** | 展向性能分布 | 这些变量影响**叶高的哪一段**？ |
| **2 维** | 子午面物理场云图 | 影响的**物理机制**是什么？ |
| 局部 | 典型样本归因 | 在这个具体设计里，各变量**贡献了多少**？ |

> 💡 传统敏感性分析止步于第 0 维。本文把它推进到"**定位到叶高位置**"和"**看到流场机制**"，这才是能指导设计的知识。

#### 5. 实验验证与量化突破

**先报胜负：** 先读结论句与最大那一格，再读全表；表是证据架不是背诵清单。

**研究对象**：GE-E3 高压涡轮**第一级**——静子 46 片、转子 76 片，转子叶尖间隙 0.3 mm。

**数值方法**［§3.1］：NUMECA 做网格与气动仿真，**Spalart–Allmaras** 湍流模型；进口总温 **719 K**、进口总压 **344.74 kPa**、出口静压 **139.473 kPa**、转速 **8279 r/min**；网格无关性研究表明网格超过约 **150 万**时效率与压比趋于稳定，最终选用约 **200 万**节点的结构网格；静子表面等熵马赫数分布与文献实验数据吻合良好。

**评价对象**：总对总效率
**〔式〕** η = (1-T*₂/T*₀)/(1-(P*₂/P*₀)^(k-1)/k)

同时监测流量变化，以保证涡轮级在设计点附近工作。

**① 显著变量识别（对级效率）**［§4.2］

| 排名 | 变量 | 含义 |
| :---: | :--- | :--- |
| **1** | **AE** | 叶片**有效出口角**，AE=arcsin(o/t)（o 为喉部直径、t 为栅距） |
| **2** | **D** | 静子**三维积叠参数**（周向中偏移 / 周向尖偏移 / 轴向尖偏移） |
| **3** | **PSL2** | 吸力面前缘附近的**样条控制点 2** |

补充发现：在静子与转子的 6 个截面中，**转子中截面 R2 与静子中截面 S2** 的影响程度高于其他截面。

**② 三条挖出来的设计准则**［§5 结论(1)–(3)］

**准则一（有效出口角 AE）**：
- **转子中截面（AE-R2）减小有效出口角 → 提升效率**；
- **静子中截面（AE-S2）增大有效出口角 → 提升效率**；
- 二者**配合**使用可在提升效率的同时**限制流量变化**。
- 1 维 SHAP 可视化进一步显示：减小 AE-R2 能提升**中段叶高**的效率，但会**牺牲上部端壁区**的效率——这是一个典型的**权衡**，而 0 维分析看不到这一点。

**准则二（静子三维积叠 D）**：
- 叶尖处**向压力侧**偏移 → 提升**叶尖**效率；
- 中截面处同样**向压力侧**偏移 → 提升**中段**效率；
- 两者共同形成**正倾斜（positively leaned）叶片**，有助于**减小静子叶道内的径向压力梯度**，从而提升涡轮效率。

**准则三（吸力面前缘样条控制点 PSL2）**：
- 把静子与转子中截面**吸力面前缘附近的样条控制点朝"叶片减薄"方向移动**，有利于**降低前缘加速区的压力梯度**，减少不可逆流动损失，从而在**大部分叶高范围**内提升效率。

**③ 最终验证**［§5 结论(4)］

| 指标 | 值 |
| :--- | :--- |
| 最终设计效率 | **91.09%** |
| 相对参考设计提升 | **+0.65%** |
| 与数据集的关系 | **超过数据集中的最大效率值** |

> 📌 **这一点特别关键**：最终设计**不是**数据集里挑出来的最好样本，而是**遵循准则重新设计**出来的，结果**比数据集里最好的还要好**。这说明挖出来的准则具有**外推价值**，而不只是对已有数据的拟合总结。

**可以攻击的点：**

1. **样本量偏小**：93 维设计空间只有 **352 个样本**（约 3.8 个样本/维）。对 XGBoost 建模尚可，但对 SHAP 的**高阶交互**估计与结论泛化都有风险。
2. **筛选引入了选择偏差**：1000 → 352 的筛选条件是"流量偏离 ≤ ±1%"。这意味着**所有结论只在这条流量约束带内成立**，不能外推到流量偏离超出 ±1% 的工况。
3. **SHAP 解释的是 XGBoost，不是真实 CFD**。虽然 XGBoost 交叉验证 RMSE 仅 0.0290%，但解释的可靠性上界**就是代理模型的精度**；在 93 维、352 样本的条件下，代理模型在样本稀疏区域可能失真，而 SHAP 无法自证。
4. **相关性 ≠ 因果性**。SHAP 给的是"在该数据集上、该模型内的贡献归因"，**不是物理因果**。三条准则的物理机制解释（径向压力梯度、前缘加速区）是作者的**后验解读**，需要独立的机理验证。
5. **未与 Sobol 指数、主动子空间做定量对比**，只在引言中引用了他人的对比结论。
6. **版本状态**：Journal Pre-proofs，无卷期页码，且日期记载存在两处不一致。

- **论文 11（DA-EGO）**：用 PCE/ANOVA 做变量交互分析，但那是**为子空间分解服务**的副产品；本文把"变量重要性"本身作为研究目标。
- **论文 18（P-ResUNet）**：用 ANOVA 圈定优化空间；本文用 SHAP，且能额外给出**影响的方向性**与**空间定位**。

**本文的独特价值**：前面十二讲都在问"**怎么找到最优解**"，本文问的是"**最优解为什么好**"——把优化留下的数据变成**可读的设计知识**。

**启后：**
- SHAP 框架可推广到多学科设计空间（原文结论明确提及）；
- 最自然的下一步是**闭环**：用 SHAP 挖出的准则**缩小设计空间**（例如把 PSL2、AE-S2 的变化范围收紧），再交给 DA-EGO / GSDE 去搜索。这样"知识发现"与"智能优化"就从两个独立环节变成一条流水线。

---

**读蜂群的纪律：**  
颜色是特征值高低，不是「好/坏」道德色。  
左右是贡献方向，依赖问题定义（最大/最小）。  
任何写入手册的句子，必须可被质检员用卡尺或图纸检查。

**可信度使用：**  
可解释 5 分 = 能开会；因果 2 分 = 不能当物理定律写进教材。  
准则卡要通过工艺与强度，不通过 = 归因项目未完成。

---

#### 附：从蜂群图到准则卡的三步

1. **看方向：** 点群偏右=该变量增大常推高目标（或反之，看问题定义）。  
2. **看颜色：** 颜色=特征值大小，用于「高值时贡献是否更毒」。  
3. **写句子：** 把「变量 #47 敏感」改成「叶中安装角避免与端弯同时取上界」。

**反派冠军无配方的会议室版：**  
「优化结果已出，请写入设计规范。」——若只能附一张外形图，规范组会退回。SHAP 是退回意见的技术回答。

#### 附：准则卡印刷厂

**不合格：** 「变量 47 很重要。」  
**合格：** 「叶中截面安装角 θ_mid 避免与端弯 δ_ew 同时取上界；优先将 θ_mid 保持在［θ_a, θ_b］（由 SHAP 蜂群与约束共同划定）。」

**从蜂群到句子的强制步骤：** 方向 → 颜色（高低特征值）→ 可执行区间 → 可检查方式（图纸/测量）。

#### 附：93 维会议室剧本（10 分钟）

**角色：** 优化工程师、设计规范员、强度/工艺代表。

1. 优化工程师出示冠军外形 + SHAP 蜂群。

#### 附：SHAP 项目的反模式清单

- 把蜂群截图当最终交付。  
- 用「显著」等词不写区间（本讲禁止空套话）。  
- 忽略工艺/强度划红，强行写激进准则。  
- 把相关当因果，向下一代设计硬推。  
- Top 贡献变量超过 10 个还不肯收敛成 ≤3 条句子。

正确交付物：**准则卡 PDF + 蜂群附录 + 划红记录。**
