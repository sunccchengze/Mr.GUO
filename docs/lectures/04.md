#### 1. 生活与物理直觉引子：为什么"分而治之"在优化里这么难

先讲一个生活场景。你要装修一套 126 个房间的超大房子，预算只够请设计师做 **1000 次**方案评审。

**笨办法**：每次都让设计师把整套房子从头到尾重新设计一遍。1000 次下来，每个房间平均只被认真推敲过 8 次——大概率烂尾。

**聪明办法**：把房子按功能分区（客厅区、卧室区、厨卫区……），**每次集中精力改一个区**，其他区保持现状；改完一个区就把它的最优方案"固化"下来，再改下一个区；改完一轮后重新审视：**哪些区之间其实互相影响**（比如开放式厨房和客厅必须一起改），把它们合并后重新规划。

这就是 DA-EGO 的核心思路。但这里有个真正的难点，也是本文的贡献所在：

> **你事先并不知道哪些房间之间互相影响。**

在叶轮机械里，这个"影响"是物理上真实存在的：改动第 1 排叶片，会改变第 2 排的进口气流角，于是第 1 排和第 2 排的变量之间存在**交互作用（interaction）**。把它们拆进不同子空间各自优化，就会得到互相矛盾的结果。

所以 DA-EGO 的关键不是"分解"，而是"**动态**分解"——**每轮迭代都重新判断谁和谁该分在一起**。

**装修监理的口令：**

- 水电墙（强交互）→ 绝不能拆到两个标段；  
- 两间不相干的客房（可分离）→ 可以轮流施工；  
- 疑似承重墙（P_S）→ 先小范围验证，再决定打不打通。

DA-EGO 的「动态」两个字，意思是：**标段划分会随着你对新房结构的理解而改**，不是一锤子合同。

**监理口令：** 水电墙不拆标段；客房可轮流；疑似承重先验。

#### 2. 叶轮机械中的真实工程死穴：GSDE 的代价与贝叶斯框架的"不甘心"

![EGO 在低维与高维的取舍，及 DA-EGO 的分解思路（rotor37 divide，手绘笔记版）](./images/L04_s2_rotor37_divide_zh.png)

> **指读：** 这张图是本讲工程死穴的一张图版本。


第 03 讲的 GSDE 用进化算法硬扛 126 维，效果很好，但它放弃了贝叶斯优化（EGO）这套东西。站在贝叶斯阵营看，这是有遗憾的：

- EGO/Kriging 的**样本效率**在**低维**问题上其实远高于进化算法——几十次评估就能逼近最优；
- 它失效的地方是**高维**：Kriging 建模失真、采集函数全局最优化本身变成难题。

于是问题变成：**能不能不动 EGO 的骨架，只把"高维"这件事解决掉？**

本文给出的答案是：**把高维问题分解成若干低维子问题，在每个子问题上用 EGO 好好优化，再把各子空间学到的知识聚合回全空间。** 而且——**分解方案每轮迭代都要更新**。

原文定义的问题规模是 **d≥ 30 的高维昂贵黑箱问题**［原文 P11 摘要］。

**现场感：** 周五下班前组长要数——你面对的不是可以慢慢推的练习题，而是**算错一次就不可回收**的预算。

##### 3C. 主路径公式与推导（知识全保留）

**第一步：什么是"变量交互"（interaction）**

设目标函数 f(x)。若变量 x_i 的取值会**改变** x_j 对 f 的影响，则称 x_i 与 x_j 存在交互。

用方差分析（ANOVA）的语言说：把 f 分解成主效应项与交互效应项
**〔式〕** f(x) = f₀ + ∑ᵢ fᵢ(xᵢ) + ∑_{i<j} f_ij(xᵢ, xⱼ) + ⋯

**回译：** 上式是主路径构件——先记住它在算法里负责哪一步，再抠每一个符号。


若 f_ij ≡ 0，则 x_i 与 x_j **可分离**，可以安全地分进不同子空间；反之必须放在同一个子空间里一起优化。

**第二步：怎么在只有稀疏样本时判断交互？——PCE 灵敏度系数**

本文用**多项式混沌展开（PCE）**的灵敏度系数 SPCE_ij 给每一对变量 (x_i, x_j) 打分。D 个变量共有

**〔式〕** (D(D-1))/(2)


个变量对（126 维时是 7875 对）。DA-EGO 把它们分成三类［原文 P11 §3.2.1］：

| 类别 | 记号 | 含义 |
| :--- | :--- | :--- |
| 确认交互 | P_C | 已由低维代理模型验证确认有交互的 t 对 |
| 疑似交互 | P_S | 在剩余变量对中 SPCE_ij 最高的一批，**待验证** |
| 非交互 | — | 其余（可能交互很弱） |

> **原文自己给出的警告（务必记住）**："由于维数灾难的存在，**高维 PCE 代理的精度有限，这会导致交互变量对的选取出现误差**。" 正因如此，P_S 中的疑似交互还要**再用低维代理模型验证确认**。

**第三步：精英点（elite-point）——子空间与全空间之间的知识桥梁**

取全部已评估样本中的**当前最优样本**作为精英点。各子空间优化得到的最优解被**组合进精英点**，再用于全空间的全局搜索。

这一步的意义是：子空间是低维的、好优化的，但它只是"局部视野"；精英点把各局部视野的最优解**拼装成一个全局可行解**，保证子空间优化不会跑偏到全空间的劣解上去。

**第四步：三类知识构成闭环**

原文把"设计空间的知识"明确定义为三类数据［原文 P11 §3］：

1. **采样数据**：所有已评估样本的坐标与函数值；
2. **变量交互关系**：已发现（确认/疑似）的交互变量对；
3. **搜索边界**：每个变量当前的搜索范围。

由此形成闭环：

```
[知识] → 构造子任务（分解方案 + 搜索范围）
            ↓
     各子空间独立做基于代理的优化
            ↓
   子任务数据挖掘（摄动法 + ANOVA 检测交互）
            ↓
[知识更新] → 下一轮的分解方案与搜索范围
```

**第五步：搜索范围收缩**

若此前求解过**相似子任务**（变量相同、精英点不同），则可依据累积经验缩小子问题的搜索范围，从而同时提升优化效率与交互分析的精度［原文 P11 §3.2.2］。

> 🧭 **值班手册：** 先看「什么情况下走哪条分支」，公式是对白速记不是主角。

```
① 初始化
     LHS 采样 50 个点并评估
     默认：任意变量间无交互
     默认：每个变量搜索范围 [0,1]

② 循环直到满足停止条件：
   (a) 高维分解
        计算所有变量对的 PCE 灵敏度系数 SPCE_ij
        分为：确认交互 PC / 疑似交互 PS / 非交互
        用低维代理模型验证 PS → 更新 PC
        据 PC 把 D 维空间分解为若干低维子空间
        取当前最优样本作为 elite-point
        若历史上有相似子任务 → 收缩该子问题的搜索范围
   (b) 子问题优化与知识挖掘
        在每个子空间上用 Kriging + EGO 采集函数优化
        用摄动法 + ANOVA 在子空间/全空间中检测变量交互
        把新发现的交互关系写回知识库
        把各子空间最优解组合进 elite-point
```

**算例二：NASA Rotor 37 跨声速压气机转子（28 变量）**

- 参数化：5 个展向截面（0/25/50/75/100% 叶高）× 各 5 个吸力面控制点 = 25 个变量，加 1 个周向平移（x26）与 2 个轴向平移（x27、x28），共 **28 维**［原文 Table 3］；

**可以攻击的点：**

1. **作者自己承认的时间复杂度问题**。原文结论原话：该方法"提高了算法的时间复杂度，导致算法自身消耗更多计算资源。虽然这对昂贵样本问题不构成阻碍，但在**样本廉价**的场景下会削弱算法性能；样本的主要计算发生在 Kriging 模型构建，可用增强 Kriging 方法加以解决"［原文 §6 Conclusions］。翻译成人话：**这套方法只在"评估很贵"时才划算**——而这恰恰是叶轮机械的场景，所以问题不大，但必须有这个前提意识。
