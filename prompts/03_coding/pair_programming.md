# 结对编程：代码实践时的 AI 伙伴

> **核心思想：** 不要让 AI 替你写代码。让它先问你"这段代码在做什么"，再给你反馈。自己解释一遍 > 被动看十遍。
>
> **使用时机：** 运行 `code/` 下的代码模块，或做项目任务时。

## Prompt（直接复制使用）

```
我正在学习白皮书第五篇的代码 [填入文件名，例如 code/optimizer.py]。
我想理解其中的 [填入具体函数，例如 calibrated_ei 函数]。

请作为结对编程伙伴，按以下步骤引导我：

1. **先让我解释**：请你先问我"这段代码在做什么"，等我用自己的话解释后，再指出我的理解是否正确。
2. **关键行解读**：指出代码中最关键的 3 行，解释它们的物理/优化含义（不是语法，是"这行代码在工程上代表什么"）。
3. **给我一个小任务**：给我一个修改参数看效果的小任务（例如"把 beta 从 0.1 改成 0.5，结果会怎样变化？为什么？"），让我自己改代码并运行。
4. **检查我的修改**：我改完后请你检查，指出对错。
5. **工程总结**：让我用自己的话总结"这个算法如何帮燃气轮机设计省钱/提效"。

每步等我完成后再进入下一步，不要一次性给完所有答案。
```

## 使用说明

- **先运行一遍代码，观察输出，再用这个 Prompt。** 不要在没运行过的情况下就让 AI 解释。
- 白皮书 `code/` 下的 10 个模块都可以单独运行自检：`python code/xxx.py`
- 修改参数时，记录"改了什么→结果怎么变→为什么"，这是最有效的学习方式

## 推荐的代码练习顺序

| 阶段 | 文件 | 练习 |

| 入门 | `code/sampling.py` | 改 `n` 和 `dim`，观察 LHS 的分层性变化 |
| 入门 | `code/rbf.py` | 换不同的核函数，比较 R² 精度 |
| 进阶 | `code/optimizer.py` | 改 `beta` 观察 CR-EI 的调度模式切换 |
| 进阶 | `code/multifidelity.py` | 改 `sigma2_df` 观察 ω 和 T 的变化 |
| 实战 | `code/moo.py` | 改 `pop_size` 和 `n_gen`，观察 Pareto 前沿变化 |
| 实战 | `code/transfer.py` | 改 `ratio` 观察加权批次的源/无标签比例 |
